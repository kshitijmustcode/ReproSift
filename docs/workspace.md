# Workspace structure

Step 2 established package locations and discovery. Steps 3–4 add the runnable dashboard and demo store.

| Location                | Manager                   | Responsibility                                          |
| ----------------------- | ------------------------- | ------------------------------------------------------- |
| apps/dashboard          | pnpm                      | Next.js dashboard (Step 3)                              |
| apps/demo-store         | pnpm                      | Separate demo store (Step 4)                            |
| packages/mcp-server     | pnpm                      | TypeScript browser MCP server                           |
| packages/browser-runner | pnpm                      | Playwright execution and test generation                |
| packages/contracts-ts   | pnpm                      | TypeScript boundary contracts                           |
| services/backend        | uv, initialized in Step 5 | Python API, worker and domain services                  |
| contracts               | Neither                   | Exported schema snapshots and cross-language examples   |
| fixtures                | Neither                   | Approved requirements and deterministic seeds           |
| evals                   | Python harness later      | Evaluation-only reports/labels and runner               |
| infra                   | Neither                   | Containers and deployment configuration when introduced |

All five JavaScript workspace members have private scoped manifests. Both apps include the same pinned Next.js, React, Tailwind CSS, TypeScript and Lucide versions; the three library members remain placeholders. pnpm discovers apps/* and packages/*; the root tooling package is also included. No nested lockfiles or workspaces should be generated by app scaffolders.

Run `pnpm dev:dashboard` on port 3000 and `pnpm dev:store` on port 3001 in separate terminals. Each application runs without the other. See [demo-store setup](../apps/demo-store/README.md) for routes and current limits.

Select Node using nvm use, then run:

```sh
pnpm install --frozen-lockfile
pnpm list -r --depth -1
pnpm format:check
```

packageManager pins pnpm; .nvmrc and .python-version pin runtimes. .npmrc enforces declared engines and saves new npm dependencies as exact versions. Internal dependencies should use workspace:* when introduced. Avoid adding fake scripts that return success for nonexistent apps or tests.

Python setup remains a separate Step 5 task. Preserve package names and placeholder ownership notes when creating applications in already-existing directories. Add only useful source folders as code is written, rather than empty domain class hierarchies.
